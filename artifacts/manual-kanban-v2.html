Manual de uso

Cómo organizar proyectos, tareas y lanzamientos con //KANBAN.

Esta guía explica el flujo de trabajo de la aplicación: crear proyectos, planificar tareas, usar el calendario, mover proyectos por el Kanban, generar el checklist automático de lanzamiento, revisar el Release Timeline y mantener tus datos guardados localmente en tu PC.

01 — Panorama general

Qué es //KANBAN

//KANBAN es un organizador local para proyectos musicales que combina calendario + tareas + Kanban + checklist de lanzamiento + Release Timeline. La aplicación guarda el trabajo como un archivo JSON en tu PC, en lugar de depender de una base de datos en la nube.

Calendario

Vista diaria y mensual para ubicar tareas, revisar pendientes y consultar una línea hora por hora.

Kanban

Cinco fases para mover cada proyecto desde Idea hasta Lanzado mediante drag & drop.

Release Timeline

Convierte la fecha de lanzamiento en una cuenta regresiva de -21 a 0 días.

Local-first

Tus proyectos y tareas viven en kanban-proyectos.json y puedes hacer backups cuando quieras.

02 — Inicio

Primeros pasos

Crea tu primer proyecto

Pulsa + Proyecto. Introduce nombre, BPM, tonalidad, fase, fecha de lanzamiento, color y notas.

Elige dónde guardar el JSON

Al guardar el primer proyecto, el navegador puede abrir el selector de archivos para crear kanban-proyectos.json. Ese archivo será la base de datos local.

Agrega tareas

Desde el calendario usa + Tarea. Define fecha, hora, tipo, workflow, proyecto, tono, color y recordatorios.

Planifica el lanzamiento

Si el proyecto tiene fecha de lanzamiento, entra a Kanban y pulsa Checklist para generar automáticamente las tareas de -21 a 0 días.

Importante: el archivo JSON es tu respaldo principal. Si el navegador no puede mantener el permiso de escritura, la aplicación descargará una copia y tendrás que volver a importarla cuando sea necesario.

04 — Proyectos

Crear y administrar proyectos

Un proyecto representa un track, EP u otro lanzamiento. Al crearlo se registra además una tarea de tipo Registro en la fecha de creación, para conservar ese hito en el calendario.

Datos disponibles

  • Emoji y nombre: identificación visual del proyecto.
  • BPM: valor entre 60 y 200.
  • Tonalidad: nota + modo mayor/menor.
  • Fase: Idea, Grabando, Mezclando, Masterizado o Lanzado.
  • Lanzamiento: fecha usada por el checklist y el Release Timeline.
  • Color de viñeta: uno de ocho colores para identificarlo.
  • Notas: referencias, letras, observaciones o información adicional.
Consejo: si un proyecto tiene fecha de lanzamiento, colócala desde el principio. Así el sistema puede calcular automáticamente el flujo de -21→0 días.
05 — Tareas

Crear, editar y completar tareas

Las tareas son independientes de los proyectos, aunque pueden vincularse a uno. Desde el calendario, una tarea puede abrirse haciendo clic sobre su título; desde otras vistas también puedes editarla.

CampoUso
Fecha + horaDeterminan cuándo aparece la tarea y cuándo puede dispararse una alarma.
TipoRecordatorio o Registro.
WorkflowComposición, Grabación, Mezcla, Masterización, Distribución, Promoción, Administrativo u Otro.
ProyectoVincula la tarea con un proyecto concreto.
TonoSelecciona el sonido de la alarma y permite probarlo desde el botón 🔊.
ViñetaColor visual de la tarea.
RecordatoriosA la hora, 24h antes, 12h antes, 7 días, 14 días o 21 días antes.

Una tarea puede marcarse como hecha con ✓. También puede editarse o eliminarse desde su interfaz correspondiente.

06 — Planificación

Cómo usar el calendario

El calendario es el centro de planificación diaria. Puedes cambiar de mes con las flechas, volver a la fecha actual con Hoy y seleccionar cualquier día para consultar sus tareas.

Resumen

Muestra cuatro cifras: TOTAL, HECHAS, HOY y PEND. Es un panorama rápido del estado de las tareas.

Día seleccionado

Lista las tareas del día, permite marcarlas como hechas y abrir su editor.

Hora por hora

Organiza las tareas desde las 08:00 hasta las 17:00 y añade horas fuera de jornada cuando existen tareas en ellas.

+ Tarea

Crea una tarea directamente para la fecha seleccionada, evitando tener que rellenar la fecha manualmente.

Semanas y días

La vista agrupa el mes en bloques semanales. Cada día muestra su nombre, número y hasta dos tareas; cuando hay más aparece +X más. Haz clic en el día para seleccionarlo.

07 — Flujo de trabajo

Kanban: cinco fases

La vista Kanban organiza los proyectos según su fase actual:

Idea

Concepto, demo o proyecto todavía en definición.

Grabando

Producción y captura de material.

Mezclando

Edición, balance y mezcla.

Masterizado

Master final y preparación del release.

Lanzado

Proyecto publicado o liberado.

Para cambiar de fase, arrastra la tarjeta del proyecto y suéltala sobre otra columna. El cambio se guarda en el estado local.

08 — Automatización

Checklist automático -21→0

Cuando un proyecto tiene fecha de lanzamiento, el botón Checklist genera ocho tareas de preparación y lanzamiento. El sistema evita duplicar el checklist si ya existe.

MomentoTarea generada
-21 díasDefinir portada + metadata (ISRC / créditos)
-14 díasSubir a distribuidora y revisar stores
-14 díasPitch editorial Spotify for Artists
-10 díasTeasers redes + pre-save link
-7 díasEnviar a prensa / curadores + mailing
-5 díasRevisar master final y loudness
-3 díasCheck copyright / splits / contratos
0 días🚀 LANZAMIENTO – activar campaña
Importante: el checklist se genera a partir de la fecha de lanzamiento del proyecto. Si cambias la fecha después de haber generado el checklist, revisa las tareas existentes antes de seguir trabajando.
09 — Release

Release Timeline

El Release Timeline transforma el checklist en una vista de cuenta regresiva. Selecciona un proyecto con fecha de lanzamiento y el sistema muestra cinco nodos:

MomentoEnfoque
-21Upload to distributor — portada + ISRC.
-14Pitch playlists — pitch editorial.
-7Cover art — teasers + prensa.
-3Promo video — master + copyright.
0Release day — lanzamiento.

Debajo aparece el checklist completo, su porcentaje de avance y un log de alarmas programadas. El timeline es principalmente informativo: las tareas siguen editándose desde el propio checklist o desde el calendario.

10 — Recordatorios

Alarmas y recordatorios

Las tareas con fecha pueden tener recordatorios asociados. La aplicación incluye distintos tonos y permite probarlos desde ⚙️ Configuración.

  • A la hora: alerta cuando llega la hora de la tarea.
  • 24h / 12h antes: avisos anticipados.
  • 7 / 14 / 21 días: recordatorios de planificación.
  • Tono: selecciona el sonido y usa 🔊 para probarlo.

Desde Configuración también puedes ejecutar una prueba de ráfaga de alarmas durante un minuto para comprobar el comportamiento del navegador.

11 — Datos

Guardar, importar y hacer backups

La aplicación está pensada para que tus datos permanezcan bajo tu control. El archivo principal es kanban-proyectos.json.

💾 Guardar JSON

Descarga o actualiza una copia del estado actual.

📂 Importar

Permite recuperar proyectos y tareas desde un archivo JSON.

Backup rápido

Crea una copia con fecha y hora para conservar puntos de restauración.

Archivo vinculado

Chrome/Edge pueden mantener un permiso de escritura y auto-guardar sobre el archivo elegido.

Recomendación: conserva backups periódicos. Si vas a hacer cambios importantes, crea primero una copia rápida con timestamp.

13 — Móvil

Uso en pantallas pequeñas

En móvil aparece una navegación inferior con accesos rápidos a Hoy, Calendario, crear tarea, Timeline y Configuración. La interfaz adapta sus columnas y tarjetas para mantener el flujo de trabajo usable en pantallas estrechas.

Consejo: para editar muchos datos de proyectos o hacer backups, una pantalla de escritorio ofrece más espacio y facilita el manejo del archivo local.
14 — Buenas prácticas

Consejos rápidos de uso

  1. Crea primero el proyecto y luego vincula las tareas a él.
  2. Define la fecha de lanzamiento temprano si sabes cuándo saldrá el material.
  3. Usa el Kanban como estado general y el calendario para el trabajo concreto del día.
  4. Marca tareas como hechas en cuanto se completen para que el progreso sea fiable.
  5. Haz backups antes de reorganizar grandes cantidades de información.
  6. Usa colores de viñeta con criterio para identificar rápidamente proyectos y tareas.
15 — Honestidad primero

Límites conocidos

  • El sistema depende del almacenamiento local del navegador y de los permisos del archivo.
  • Si el navegador no permite mantener el vínculo con el archivo, tendrás que exportar/importar JSON manualmente.
  • El Release Timeline se basa en las tareas del checklist generado; no sustituye un calendario externo ni una plataforma de distribución.
  • Las alarmas dependen de que la aplicación y el navegador puedan ejecutar el temporizador correspondiente.
Regla de oro: si tu trabajo es importante, conserva una copia del JSON fuera del archivo principal.
